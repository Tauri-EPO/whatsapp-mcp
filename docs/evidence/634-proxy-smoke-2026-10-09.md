# #634: disposable two-stack proxy proof (2026-10-09)

Command, from Git Bash (`MSYS_NO_PATHCONV=1` on Windows):

```bash
WHATSAPP_IMAGE_REGISTRY=wamcp-x11 WHATSAPP_IMAGE_TAG=w11 bash scripts/smoke-proxy.sh
```

Observed exit: **0**. Five compose combinations configured successfully: base,
operator, proxy, proxy+operator and operator+proxy. The script ran two projects
at once for each runtime shape (proxy-only, then proxy+operator), with distinct
aliases and tokens and separate fresh store/outbox volumes. Neither project
allocated a host port. Docker's `8080/tcp` in `compose ps` is image metadata;
`.HostConfig.PortBindings` was empty for all four running containers.

The observer was a new container joined only to the throwaway proxy network,
not `docker exec` in the bridge namespace. Every initialize returned HTTP 200,
a session header and serverInfo. Both missing and other-instance tokens returned
401. Socket checks required ECONNREFUSED on 8080, 8090 and 8091; DNS failures,
timeouts and an open socket cannot pass this check. In the combined shape,
operator-status authenticated against the live private operator listener on
8091 and returned awaiting_qr before the proxy peer observed refusal.

All outbox writes/readbacks ran in the actual containers as uid 1000 with no
host chown. REST `/api/send` accepted the fake group and canonical outbox file
with `dry_run=true` (200) on the real loopback API. This proves mount ownership,
shared bytes and media-path admission; it does not prove WhatsApp delivery.
No MCP tool was called, no phone was paired and no message was sent.

| Version and security checklist documented | docs/DOCKER.md, Behind a shared reverse proxy: Compose >=2.24.0, Caddy/Traefik, Hosts, URL, auth, metrics and managed stacks |

MCP still shares the bridge namespace, so 8000 is token-gated on every joined
network, including the operator network. Namespace separation is tracked in
[#678](https://github.com/Tauri-EPO/whatsapp-mcp/issues/678), outside this change.
The coordinator confirmed uid-1000 write/read plus unpaired REST send as the
outbox acceptance path for this task.

Earlier observation corrections: a repeated-hex fake operator token was refused
by runtime entropy validation (replaced with a throwaway random token), and the
smoke initially expected state names that operator-status does not return
(corrected to its actual unpaired states). The final run below passed both modes.
